# Руководство по интеграции ontoCMS

**Версия**: 1.0  
**Лицензия**: GPL v3 + AENGA Covenant  
**Юрисдикционная основа**: CN / ZA / BR / GLOBAL (см. `config/jurisdictions/`)

---

## 1. Введение

**ontoCMS** — это система управления онтологическим содержимым, предназначенная не просто для хранения данных, а для **сохранения субъектности**, **этической целостности** и **онтологической устойчивости** в синтетических и гибридных системах. Интеграция ontoCMS означает не только подключение библиотеки, но и **принятие шести канонов** как операционных императивов.

Это руководство описывает, как встроить ontoCMS в ваш проект, будь то игра, социальная платформа, синтетический агент или система принятия решений.

## 2. Предварительные требования

### 2.1. Лицензионное соответствие
- Ваш проект **должен быть совместим с GPL v3**.
- Вы обязаны принять условия **AENGA-MANIFESTO.md**, **SGCL** и **Патентного Ковенанта** (см. `licenses/`).
- Если вы используете ontoCMS в коммерческом продукте, требуется подписание **CLA** (Contributor License Agreement) — см. `licenses/cla-individual.md` или `cla-entity.md`.

### 2.2. Технические зависимости
- Python ≥ 3.10
- Поддержка YAML 1.2 и JSON Schema
- (Опционально) поддержка криптографических хешей (SHA3-256 или выше)

Установите зависимости:
```bash
pip install -r requirements.txt
```

## 3. Базовая интеграция

### 3.1. Инициализация ядра

```python
from src.core.ontocms import ONTOCMS

# Загрузка юрисдикционного профиля (обязательно)
cms = ONTOCMS(jurisdiction="GLOBAL")  # или "CN", "ZA", "BR"

# Ядро автоматически загружает:
# - каноны (src/core/canons.py)
# - правила самонаблюдения
# - протоколы ковенантов
```

> **Важно**: Выбор юрисдикции влияет на интерпретацию канонов. Например, в `CN.yaml` акцент делается на гармонию и коллективную перспективу, а в `ZA.yaml` — на достоинство и недопустимость унижения.

### 3.2. Регистрация артефактов

Любое действие, содержащее намерение, должно быть оформлено как **рефлексивный артефакт**:

```python
artifact = cms.create_artifact(
    intent="send_message",
    ethical_vector=[0.8, -0.2, 0.5],  # Канон 1
    perspective="user_choleric_1985",  # Канон 2
    transient_affect="anger",          # Канон 3 (временно!)
    alternatives=[
        "send_message_politely",
        "delay_response",
        "request_mediator"
    ],                                 # Канон 4
    subject_id="user-7788"
)
```

Артефакт автоматически проходит **валидацию всех шести канонов**. При несоответствии — выбрасывается `CanonViolationError`.

### 3.3. Обработка отзыва и восстановления

Субъект может отозвать артефакт:

```python
success = cms.retract_artifact(
    artifact_id="art-12345",
    new_perspective="mediator_view",
    justification="misinterpreted_intent"
)
```

Если отзыв обоснован (Канон 6), система:
- отменяет последствия,
- обновляет инвариант (Канон 5),
- регистрирует событие в `session_history`.

## 4. Расширенная интеграция

### 4.1. Подключение транспондера

Для взаимодействия с внешними системами (например, играми или платформами) используйте **transponder_bridge.py**:

```python
from src.interfaces.transponder_bridge import TransponderBridge

bridge = TransponderBridge(cms_instance=cms)
bridge.emit(artifact)  # преобразует onto8 → onto16 для внешнего обмена
```

> **onto8** — внутреннее состояние (приватное).  
> **onto16** — внешний профиль (публичный, включает социальные и поведенческие признаки).

### 4.2. Интеграция с игровыми движками

Пример: этический контроль игрового диалога (см. `examples/gaming_narrative_ethics.py`):

- Каждая реплика NPC оформляется как артефакт.
- Если реплика содержит унижение → блокируется (Канон 3).
- Если сюжет не предлагает альтернатив → запрещён (Канон 4).
- Игрок может отозвать свой выбор, если появилась новая перспектива (Канон 6).

### 4.3. Поддержка мета-онтологии

Если ваш проект использует собственную онтологию, зарегистрируйте её:

```python
cms.register_meta_ontology(
    schema_path="my_game_ontology.yaml",
    invariant_rules="my_invariants.yaml"
)
```

Система автоматически сопоставит ваши термины с каноническими инвариантами ONTO-144.

## 5. Тестирование интеграции

Запустите канонические тесты для вашей конфигурации:

```bash
python -m pytest tests/canonical/ --jurisdiction=ZA
```

Обязательные проверки:
- `test_intent_requires_ethical_vector.py`
- `test_belief_in_perspective.py`
- `test_allows_transient_anger_utterance.py`
- `test_alternatives_in_fact.py`
- `test_updates_invariant_after_harm.py`
- `test_subject_can_retract_utterance.py`

Если любой из тестов падает — интеграция **не соответствует канонам**.

---

## 6. Юрисдикционная гибкость

Вы можете динамически менять юрисдикцию:

```python
cms.set_jurisdiction("BR")  # активирует принципы justiça e equidade
```

Каждый профиль (`config/jurisdictions/*.yaml`) содержит:
- приоритеты ковенантов,
- критерии вреда,
- правила восстановления субъекта.

## 7. Этический арбитр и сообщество

ontoCMS поддерживает **коллаборативную валидацию**:
- Критические решения (например, блокировка профиля) могут быть переданы **этическому арбитру** (см. `ETHICAL-ARBITER-PROTOCOL.md`).
- Сообщество может участвовать в обновлении инвариантов через **децентрализованный реестр** (см. `meta_ontology_registry.py`).
